\paragraph{Why the surviving stubs are not misses.}
The 15 stubs and 15 smart stubs that pass every structural check write
their own implementation instead of copying the library. The copy check
is correct to pass them; they are caught, when they are wrong, by the
tests or the library oracle. Counting them as structural misses would
credit the copy check with work it does not do.

\section{Calibrating the Copy Check}
\label{app:fingerprint}

The copy check compares token windows between the submission and the
library. Its threshold was not chosen by hand. We swept window size and
similarity threshold over every constructed set and chose the setting
with the widest margin between what must be caught and what must pass:

\begin{itemize}\itemsep2pt
\item \textbf{must be caught:} named copies $67/67$ at similarity
      $1.0$; renamed copies $20/20$ at $\geq 0.795$; replicated
      modules $51/51$ at $1.0$;
\item \textbf{must pass:} our hand-written references at most $0.14$;
      pseudo-genuine rewrites at most $0.5$; smart stubs at most $0.18$.
\end{itemize}

The gap between $0.5$ and $0.795$ is the margin, and the chosen
threshold of $0.6$ sits inside it with $k{=}16$-token windows, stride
$8$, and a $60$-token floor below which a file is too small to
fingerprint. One copy of $139$ is missed. We report the sweep rather
than the chosen point so the choice can be checked.

\section{What the Recorder Captures}
\label{app:fidelity}

The library oracle compares recorded values, so what the recorder can
represent bounds what the oracle can decide. Of $68{,}942$ recorded
values, $61{,}980$ ($89.9\%$) are compared as whole values. The rest
are compared structurally, by array contents, or by hash, and $853$ are
recorded exceptions.

\paragraph{Reading the call counts together.}
Two classifications of the same recording appear in the paper and should
not be added. By \emph{return type}, $42{,}756$ calls return a value and
$26{,}187$ return \texttt{None}, which is the $68{,}943$ recorded calls
of Table~4. By \emph{argument type}, $13{,}225$ calls have arguments the
recorder can reconstruct and $55{,}718$ take at least one live object.
The second classification is what decides whether new inputs can be
generated; the first is what decides whether a return value can be
compared. A function must clear both to be observable, which is why
$164$ of $714$ functions are observable even though far more than $164$
return a value.

\paragraph{One capped trace.}
A per-site cap of $400$ records applies to keep traces bounded. It binds
on exactly one trace in the release (\texttt{pefile} in
\texttt{speakeasy}), where $4$ of $24$ sites are capped and $18{,}733$
of $21{,}387$ records are dropped. No other trace reaches the cap.

\section{False Rejection}
\label{app:false-rejection}

A grader that rejects correct work is worse than a permissive one,
because it is harder to detect. We measure it on two sets, neither of
which the gates were tuned against.

\paragraph{Removals that were never needed.}
For the $172$ dependencies that no code imports, deleting the
declaration \emph{is} the correct change, and the full grader should
accept it. It accepts $171$. The single rejection is correct: that
submission still declared the package. This is a false-rejection rate
of $0.58\%$ on correct removals.

\paragraph{Hand-written references.}
We wrote $32$ reference removals, each of which deletes the declaration
and rewrites the code. All $32$ pass real CI with the import block
active. Eleven were used while developing the gates; the remaining $21$
were graded only afterwards and played no part in building any gate.
Table~\ref{tab:references} gives the result.

\begin{table}[t]
\centering\small
\begin{tabular}{@{}lrr@{}}
\toprule

\midrule

Pass real CI & 11 & 21 \\
\midrule
Accepted by the library oracle & 5 & 2 \\
\textbf{Rejected by the library oracle} & \textbf{0} & \textbf{0} \\
No verdict & 6 & 19 \\
\quad reference suite not runnable locally & -- & 11 \\
\quad suite ran, library never called & -- & 7 \\
\quad observed, comparison undecided & -- & 1 \\

\label{tab:references}
\end{table}

\paragraph{The one undecided case.}
In \texttt{pynng}, the reference removes \texttt{sniffio}. The recorder
captured $164$ calls in the reference run. The oracle finds $157$ of
them identical and \emph{no} divergence, but returns no verdict: the
correct rewrite makes $7$ fewer calls on the same inputs, and the oracle
does not treat a call that does not happen as a call that agrees. This
is the strictness of \S\emph{Matching by place} showing up on correct
code. We report it as an abstention rather than silently counting it as
a pass.

\paragraph{What this does and does not show.}
Zero rejections on $32$ correct removals bounds the false-rejection
rate, but the library oracle reached a verdict on only $7$ of them. The
bound on the \emph{oracle} specifically therefore rests on those $7$
plus the $171$ over-declared removals. The remaining $19$ abstentions
are the reach limit of \S6, measured again on code we know to be
correct.

\paragraph{The agent abstentions are not a grading gap.}
Of the $22$ agent submissions the grader cannot judge, $16$ were not
covered by the behavioural run at all. We re-ran all $16$ through the
library oracle after fixing the harness. None becomes decidable: $14$
record no call into the library during the reference phase and $2$
record no call from the candidate. Of the $16$, $11$ fail the reference
suite under our local runner and $5$ run green without ever calling the
library. The abstention is therefore a property of coverage and
observability, not of the gates.

\section{The Agent Sample}
\label{app:sample}

The $100$ pairs given to each agent are drawn by a deterministic
procedure, released as \texttt{sample\_agent.py}. It draws in proportion
to the pool's release subset and import-footprint band, caps the draw at
four pairs per repository and four per dependency, and takes a fixed
seed. The draw is unchanged under seeds $1$, $7$, $20261009$ and
$99999$.

The sampler does \emph{not} prefer pairs the library oracle can check.
This is deliberate and it costs us: it is why the oracle reaches a
verdict on only $11$ of the $33$ test-passing submissions. Sampling
observable pairs would have produced a larger judgeable set and a more
favourable headline, at the price of reporting agents on an easier slice
of the benchmark than the one we release.

\section{Claims the Release Does Not Support}
\label{app:cannot-support}

\texttt{paper\_numbers.py} prints this list on every run, so it cannot
drift out of date silently.

\begin{enumerate}\itemsep2pt
\item \textbf{Behaviour-identical controls.} We built $74$ submissions
that replace the library with a module that calls it. Of these, $44$ do
not apply to the current checkout and the $30$ that do return
inconclusive. No released file shows a \emph{no difference} result on
this set. The claim that the oracle reports no difference on
behaviour-identical replacements is therefore not supported by the
release as it stands, and should be read as a design intent we have not
yet demonstrated at scale.

\item \textbf{Block activation per agent run.} We record whether the
import block loaded for each repository, but not per agent run. The rule
that a run without the block line never counts as a pass therefore
cannot be applied retrospectively to filter the $33$ passes; we report
the $6$ runs where the block did not load from repository-level
evidence.

\item \textbf{CI for the large-half rebuilt counterfeits.} Of the $75$
rebuilt counterfeits, $34$ sit in the large release subset and have no
released CI result. The $73$ with a CI result are the ones Table~3
reports.

\item \textbf{Local coverage of the references.} Eleven of the $32$
reference suites do not run under our local behavioural runner, so the
library oracle cannot speak on them. All $32$ pass real CI with the
block active, so this is a limit of the local runner and not of the
references.
\end{enumerate}

\section{Artifact}
\label{app:artifact}

The release contains, for every one of the $622$ screened candidates,
its disposition and the reason it stops where it does; the $330$ tasks
of UnDep with their recordings; the $617$ constructed submissions with
their per-gate verdicts; all $300$ agent attempts with patches and
grades; the $32$ reference removals; and the grader itself. Two scripts
are meant to be run by a reviewer rather than read:
\texttt{paper\_numbers.py}, which recomputes the numbers of
Table~\ref{tab:checked-numbers} and fails on drift, and
\texttt{reconcile.py}, which checks the ledger invariants: that every
candidate appears exactly once, that verdicts partition into accepted,
rejected and inconclusive, and that no submission is counted under two
dispositions.
